  • User-interface prototyping
  • Usability laboratory testing
📨 2. Indirect methods
  • Paper survey or questionnaire
  • Electronic survey or questionnaire
  • E-mail
  • Electronic focus group

    Developing conceptual models — 10 guidelines

    slide 42
    In one line: The conceptual model must match how the user thinks, look like the real world, behave predictably, show what’s hidden, give feedback, stay consistent — for novices and experts.

    3.2

    Defining objects

    slide 43
    In one line: List every object users manipulate — with its behaviour, relationships, actions and state — then make the most important, most frequent ones very obvious and easy to use.
    • Determine all objects that have to be manipulated:
      • the objects used in tasks
      • object behaviour and characteristics that differentiate each kind
      • relationships of objects to each other and to the people using them
      • the actions performed
      • the objects to which actions apply
      • state information or attributes for each object
    • Identify the objects and actions that appear most often in the workflow.
    • Make the several most important objects very obvious and easy to manipulate.

    4.1

    Design standards or style guides — value for users & developers

    slides 45–46
    In one line: A style guide = one rulebook for how the interface looks and behaves. Users get speed, fewer errors, less training, satisfaction; developers get simpler design, less repeated work, a quality benchmark.
    👩 Value for users
    • Faster performance
    • Reduce errors
    • Reduce training time
    • Better system utilisation
    • Improve satisfaction
    • Improve system acceptance
    • Reduce development and support costs
    👨‍💻 Value for developers
    • Increase visibility of the human-computer interface
    • Simplify design
    • More programming & design aids → less programming time
    • Reduce redundant effort
    • Reduce training time
    • Provide a benchmark for quality-control testing
    Real example

    Every iPhone app puts “Back” at the top-left because Apple’s style guide says so → you learn it once and use every app faster (users). The app’s team doesn’t argue about where “Back” goes and testers can check it against the guide (developers).

    Memory hook

    “Reduce training time” appears in both lists — a classic trick question.

    Interface design goals

    slide 9
    In one line: Reduce the user’s visual, intellectual, memory and motor work, and remove burdens imposed by technology.

    d

    Screen and web page meaning and purpose — signals vs noise

    slides 11–14
    In one line: Everything on the screen must have meaning and a purpose. Useful information = signal; useless information = noise. Maximise signals, minimise noise.

    Elements that must each have meaning and purpose: every control · each screen element · all text · the screen organisation · each colour · every graphic · all animation · each message · all forms of feedback.

    signal vs noise
    Noise level:0
    ✈️ Flight EK201 — Gate B23 — Boarding 14:05
    SIGNAL

    Noise — what the slide says

    • Noise reduces clarity because useful information is diluted; it distracts, competes for attention, and contributes to information overload.
    • Goal: present information efficiently, simply, clearly, concisely and appropriately; remove all unnecessary elements.
    • A signal can become noise (and noise a signal) depending on what the user needs at that moment — so which is which should be immediately obvious.

    Organising elements clearly and meaningfully (slide 14)

    Visual clarity comes from organising elements in meaningful, understandable, recognisable ways. It is influenced by: consistency in design, a visually pleasing composition, a logical and sequential ordering, the proper amount of information, groupings and alignment. Avoid visual clutter: indistinct elements, random placement, confusing patterns.

    Slide 12 — examples of bad UI: crowded pages, unclear lift buttons, cluttered toolbars.
    Signal becomes noise — example

    The “Boarding” banner is a signal while you wait at the airport. Once you’re on the plane, the same banner is noise. A good app hides it or makes it small after boarding.

    Memory hook

    Signal = useful, Noise = useless. Think of a radio 📻: turn the noise down, the music (signal) comes through.

    Consistency

    slide 15
    In one line: Same rules everywhere — follow the real world and your own conventions; break them only when it clearly helps the user.
    • Provide real-world consistency.
    • Follow the same conventions and rules across all related interfaces.
    • Deviate only when there is a clear benefit for the user.
    animation

    More examples
    • Real-world: a green light = go, red = stop; a 🔒 padlock = secure.
    • Same conventions: Microsoft Word, Excel and PowerPoint all have File at the far left and the same ribbon style.
    • Clear-benefit deviation: “Delete account” is made red and placed apart from the other buttons on purpose, so nobody clicks it by mistake.

    slides 16–19

    Ordering of screen data and content

    slides 20–21
    In one line: Choose an ordering scheme (6 options), split information into logical units, and show only what the task needs.
    pick a scheme

      • Possible ordering schemes: Conventional (the customary way people are used to) · Function (by parameters, purpose) · Sequence of use · Importance (by priority) · Frequency of use · General to specific (website organisation).
      • Divide information into units that are logical, meaningful and sensible.
      • Only information relevant to the user’s tasks or needs appears on the screen.

      Ordering Web pages

      • Establish levels of importance (high → low).
      • Critical information near the top of the Web site; important items near the top of a page.
      • Organise information clearly; place important items consistently.
      • Facilitate scanning (not zig-zagging).
      • Structure for easy comparison (to minimise memory use).

      Typography (slides 37–41)

      A font’s characteristics can…
      • Communicate the organisation of elements
      • Identify the most important elements
      • Establish a reading order
      • Create a mood
      Font size
      • No more than 3 sizes (consider “x” height)
      • Graphical systems: 12 pt menus, 10 pt windows
      • Web: 12–14 pt body, 18–36 pt titles/headings
      • Line spacing 1 to 1½ × font size
      • Never shrink established sizes to squeeze in text
      Font styles
      • Italics → call attention
      • Bold → call attention or create hierarchy
      • Underline → on the Web, only for navigation links
      Defaults & consistency
      • GUI: standard system fonts · Web: default browser fonts
      • The user may change the fonts
      • Consistent hierarchy: one font per level of importance
      • Show hierarchy with size, weight, colour
      font size playground
      Memory hook

      Legibility = SEE, Readability = UNDERSTAND. Font purposes: “Only Important Readers Matter” (Organisation, Importance, Reading order, Mood). Hierarchy = S-W-C (Size, Weight, Colour). Menus 12 > windows 10 (you click menus). Max 3 sizes.

      Intranet & Extranet design guidelines

      slides 67–68
      In one line: Intranet (inside the company) = one home page with directory, search and news, a 4-area layout, and its own visual style.
      • Single home page with at least: directory hierarchy, search facility, current news.
      • Home page layout: top horizontal bar, left column, middle area, right column.
      • Visual style that is different, distinguishing, unified.

      Extranet (slide 68 — site for partners/clients outside the company)

      • Orient the website toward tasks.
      • Include many options and features.
      • Develop a strong navigational system.
      • To distinguish the extranet from the Internet, use a subtle difference in visual style and navigation.
      • Provide links to the public Internet site.
      Example

      A university intranet (staff only): search bar on top, department directory on the left, today’s news in the middle, quick links on the right. A supplier extranet (for partner companies): task-oriented (“submit invoice”, “track payment”), looks slightly different from the public website, with a link back to it.
